Unitful.jl

Unitful.jl supports physical units and dimensional analysis.

Compat

Using the Unitful extension with JuMP requires Julia v1.9 or later.

The Unitful extension in JuMP lets you create variables with units, and it automatically converts the units of the constraints and objective.

License

Unitful.jl is licensed under the MIT license.

Installation

Install Unitful using Pkg.add:

import PkgPkg.add("Unitful")

Use with JuMP

Activate the extension by loading both JuMP and Unitful:

julia> using JuMP, Unitfuljulia> import HiGHS

Variables with units

Create a variable with units by passing the unit as a positional argument to @variable:

julia> model = Model(HiGHS.Optimizer);julia> set_silent(model)julia> @variable(model, x >= 0u"m/s", u"m/s")(x) m s^-1julia> @variable(model, y >= 0u"m/s", u"ft/s")(y) ft s^-1

The bounds and start values must have units, even if they are zero:

julia> @variable(model, z >= 0, u"m/s")ERROR: At none:1: `@variable(model, z >= 0, u"m/s")`:Unable to use `0` as a bound or start value because it has no units.Use a quantity with the same dimension as `m s^-1`.Stacktrace:[...]

Similarly to Complex number support, x is not a VariableRef; instead, it is an affine expression with Unitful.Quantity-valued coefficients:

julia> typeof(x)GenericAffExpr{Quantity{Float64, 𝐋 𝐓^-1, Unitful.FreeUnits{(m, s^-1), 𝐋 𝐓^-1, nothing}}, VariableRef}

Behind the scenes, JuMP has created real-valued variables without units:

julia> all_variables(model)2-element Vector{VariableRef}: x y

To improve the scaling of the problem, pass a quantity instead of a unit:

julia> using JuMP, Unitfuljulia> model = Model();julia> @variable(model, 0u"m/s" <= w <= 100u"m/s", 10u"m/s")(10 w) m s^-1julia> upper_bound(only(all_variables(model)))10.0

Here, w is the expression 10.0u"m/s" * w, where the variable w without units is between 0 and 10.

Expressions with units

The unit of an expression is the unit of its coefficient type. If all its terms have the same unit, the expression keeps this unit:

julia> y + 1u"ft/s"(y + 1) ft s^-1

If the terms have different units of the same dimension, Unitful converts them to the preferred unit of this dimension, regardless of the order of the terms. See Unitful.upreferred and Unitful.preferunits for details. By default, the preferred units are the SI units:

julia> y + x(0.3048 y + x) m s^-1julia> Unitful.upreferred(u"ft/s")m s^-1

Constraints with units

When adding a constraint, the units are converted to the unit of the expression lhs - rhs, as defined in Expressions with units, and then removed:

julia> @constraint(model, c1, x + y <= 72u"km/hr")c1 : x + 0.3048 y ≤ 20

Pass a unit as a positional argument to @constraint to choose the unit of the constraint, for example, for better scaling:

julia> @constraint(model, c2, x + y <= 72u"km/hr", u"km/hr")c2 : 3.6 x + 1.09728 y ≤ 72

Note that a number like 0.5 has no unit, so the units of both sides of the following constraint are compatible:

julia> @constraint(model, c3, x <= 0.5 * y)c3 : x - 0.1524 y ≤ 0

Constraints with incompatible units throw an error:

julia> @constraint(model, x <= 1u"m")ERROR: DimensionError: 0.0 m s^-1 and 0 m are not dimensionally compatible.[...]

Objective with units

When setting the objective, the units are converted to the unit of the expression and then removed:

julia> @objective(model, Max, 2 * x + y)(2 x + 0.3048 y) m s^-1julia> objective_function(model)2 x + 0.3048 y

Solutions with units

Querying the value of an expression with units returns a value with units:

julia> optimize!(model)julia> value(x)6.666666666666667 m s^-1julia> value(y)43.744531933508306 ft s^-1julia> value(x + y)20.0 m s^-1

However, because the constraints and objective are passed to the solver without units, solution values such as objective_value and dual do not have units:

julia> objective_value(model)26.666666666666664
